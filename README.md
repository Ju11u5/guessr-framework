# 猜一猜 · 通用竞猜框架 & 弗一把推理助手

两个东西，共用一个思路：**把「猜目标」这类游戏的判定逻辑抽出来，交给数据驱动**。

| 文件 | 是什么 |
| --- | --- |
| **`guessr-framework.html`** | **通用竞猜框架**。上传任意数据（CSV/JSON）→ 自动生成一个「猜目标」游戏 + 推理助手。内容不限：CS 选手、动漫角色、球星、城市、元素、乐队…… |
| `friberg-assistant.html` | 早期做的 **CS 专用**推理助手（弗一把 / BLAST Counter-Strikle 玩法），逻辑已按官方公开规则写死，稳定可用 |

两个都是**单文件、离线、零依赖**，双击即用。整个工具不联网、不调用任何游戏接口、不绕过任何验证、不代替你提交任何东西 —— 纯粹的"纸笔加强版"。

> 非官方第三方作品，与相关游戏及其作者无隶属关系。
> 玩法和规则整理自 **[弗一把](https://shnlfriberg.online/)**（作者 [shnlfriberg](https://github.com/shnlfriberg)，源码 [csgofriberg](https://github.com/shnlfriberg/csgofriberg)）—— **完整致谢见文末**。

# 一、通用竞猜框架 `guessr-framework.html`

## 三步上手

1. **上传数据** → 「数据集」页：把表格粘进去（首行是表头）或拖入 `.csv` / `.tsv` / `.json`，点「解析并预览」。
   也可以先点「载入示例数据」看看效果（内置元素周期表前 36 号，公开事实数据）。
2. **调规则** → 框架会按列自动推断比较规则，逐列可改。**这是框架的核心**：

   | 规则 | 绿的条件 | 黄的条件 | 适合的列 |
   | --- | --- | --- | --- |
   | 完全相同 | 值一样 | 不会黄 | 名称、位置、状态、类别 |
   | 文本宽松 | 忽略大小写/空格后一样 | 不会黄 | 大小写不统一的昵称、符号 |
   | 数值接近 | 数值一样 | 差值 ≤ 容差（带 ↑↓ 方向） | 年龄、身高、数量、年份 |
   | 同组即算接近 | 值一样 | 同属一组（关联列填分组列名，或分组映射表名） | 国家→赛区、城市→省份 |
   | 命中列表即算接近 | 值一样 | 该值出现在目标的另一个列表列里 | 当前队伍 vs 历史队伍 |
   | 集合有交集 | 集合完全相同 | 有任意一个共同元素 | 标签、技能、配音阵容 |

3. **开始玩** → 「对局」页，两种数据来源、两种玩法：

   - **本地出题**：页面自己随机藏一个目标并自动算反馈 —— 一个人就能玩，适合测试数据集或自娱。
   - **外部裁判**：你在别处（网站 / 群友出题）玩，把每格反馈手工点出来录进去，它当参谋。
   - **猜名**：一次猜一个目标，看各列反馈缩小范围。
   - **属性提问**：像海龟汤一样问「他的某属性是某值吗」，只回答 是 / 是也不是 / 不是，不给方向。

   两种模式下都会实时给建议：猜名给「最该猜谁」，提问给「最该问哪个属性的哪个值」，
   算法是**最小化期望剩余候选数**。用内置示例数据实测：36 个候选平均 **2.6 步**锁定，最差 3 步。

## 数据格式

CSV / TSV（带表头）或 JSON 对象数组，一行 = 一个可猜的目标。数值列自动识别成数字；
用 `/` 或 `,` 分隔的多值会识别成列表（配合「命中列表」「集合有交集」规则用）。

```
名称,队伍,历史队伍,国家/地区,年龄,位置,Major冠军,Major参赛,状态
选手甲,MOUZ,FaZe/NAVI,瑞典,25,狙击手,1,6,现役
选手乙,NAVI,G2,乌克兰,28,步枪手,0,11,现役
```

导入时选「CS 选手」预设，就会自动套用：队伍=命中历史队伍、国家=同组（赛区）、年龄容差 3、Major 容差 1。

数据集和存档都是普通 JSON，可以直接发给别人导入。

# 二、CS 专用：弗一把推理助手 `friberg-assistant.html`

玩法固定为弗一把：普通模式 8 次猜名（反馈有颜色 + 大小箭头）/ 海龟汤 18 次提问；
判定逻辑按官方公开规则写死，稳定可用。

## 选手数据从哪来

**本仓库不包含任何选手数据**（原因见下节）。打开后候选池是空的，三条路补上：

1. **游戏内查选手页**：把名字（或整行）复制下来，粘到「候选池」页的导入框；只导入昵称也能用，属性会在你每次猜到他时自动补全。
2. **自己写 `players.js`**（放在 HTML 同目录，页面会自动载入）：

   ```js
   window.FRIBERG_DATA_EXT = {
     meta: { count: 1, source: '自己整理', generatedAt: '2026-01-01', baseYear: 2026 },
     raw: [
       // [昵称, 国家/地区, 赛区, 队伍, 出生年, 位置, Major冠军数, Major参赛数, 是否现役, 是否简单版]
       ['选手甲', '瑞典', 'europe', 'MOUZ', 2001, 'awper', 1, 6, 1, 1]
     ],
     officialRegion: { '瑞典': '欧洲' }   // 可选：国家 → 赛区
   };
   ```

   赛区键名：`europe` `cis` `asia` `oceania` `northAmerica` `southAmerica` `africaIsrael`；
   位置键名：`rifler` `awper` `coach`。
3. **导出 / 导入存档**：工具里录过的选手会自动进池，随时导出 JSON 备份。

## 为什么数据不在仓库里

游戏/网页源码是公开的（[shnlfriberg/csgofriberg](https://github.com/shnlfriberg/csgofriberg)），但许可证是 **AGPL-3.0**：
一旦把来自它的编译数据放进本仓库再分发，整个仓库都得按 AGPL-3.0 走，连带源码公开等义务。

而且那份选手数据文件后来被作者**主动从版本控制里移除了**（`chore: stop tracking generated import files`），
原始名单也一直在 `.gitignore` 里 —— 这个意图很清楚：不想让它作为项目文件被到处传。

所以本仓库只放代码，这也是对作者意愿的尊重。要用内置数据库，自己按上面的方式准备数据源；
若确实想基于上游数据分发，请遵守 AGPL-3.0，或更稳妥地去问一下作者。

# 三、打包成 exe

两个工具都能打包成单文件 exe（约 7 MB，双击即用）：

```bash
python app/build.py            # 两个都打
python app/build.py guessr     # 只打「猜一猜」
python app/build.py friberg    # 只打「弗一把助手」
```

产物在 `dist/`：`猜一猜.exe`、`弗一把助手.exe`。双击后用系统里的 Chrome / Edge 以「应用模式」
打开一个没有地址栏的独立窗口；页面与数据会释放到 exe 同目录，数据存在旁边的 `profile/` 里，
与平时浏览器的数据隔离。同一个启动器靠包内的 `app.json` 清单区分开哪个页面、带哪些数据。

```bash
猜一猜.exe --dry-run         # 只打印路径与实际启动命令，不启动（排查用）
猜一猜.exe --shortcut        # 启动并在桌面建快捷方式
猜一猜.exe --shortcut-only   # 只建快捷方式
猜一猜.exe --print-dir       # 打印数据目录
```

# 目录结构

```
guessr-framework.html     通用竞猜框架（单文件，无数据）
friberg-assistant.html    CS 专用推理助手（单文件，无数据）
players.js                选手数据（本地生成，不进仓库）
app/
  launcher.py             exe 启动器（纯标准库）
  build.py                一键打包
  make_icon.py            图标生成（纯标准库手写 PNG→ICO，不依赖 Pillow）
  version_info.txt        版本信息
data/                     数据源与中间产物（不进仓库）
tests/
  framework.test.js       框架引擎断言 56 项（含模拟整局对局收敛性）
  engine.test.js          CS 助手引擎断言 47~76 项
  perf.test.js            推荐质量 + 快慢两条实现交叉验证 14 项
  test-exe.py             exe 行为验证 15 项
  make-fw-test.js         生成框架的端到端测试页
  make-ui-test.js         生成 CS 助手的端到端测试页
  build-db.js             由数据源生成 players.js
```

# 开发

```bash
node tests/framework.test.js     # 框架引擎
node tests/engine.test.js        # CS 助手引擎
node tests/perf.test.js          # 推荐质量与性能
node tests/make-fw-test.js       # 生成端到端测试页
chrome --headless=new --dump-dom tests/fw-test.html | grep RESULT::
python tests/test-exe.py         # 验证 exe（需要先 app/build.py）
```

改完 HTML 重新打包 exe 即可，数据文件会被一起带上。
